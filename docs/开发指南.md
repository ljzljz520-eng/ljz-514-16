# 开发指南（中文）

## 1. 目录结构
- `frontend/`：前端（Vite + React）
- `backend/`：后端（Java + Maven）
- `docs/`：项目文档
- `docker-compose.yml`：一键编排

## 2. 本地启动（推荐 Docker）
在项目根目录执行：
```bash
docker compose up -d --build
```

访问：
- 前端：`http://localhost:3514/`
- 后端：`http://localhost:8514/api/health`

## 3. 前端开发

### 3.1 安装依赖
```bash
pnpm -C frontend install
```

### 3.2 开发模式
```bash
pnpm -C frontend dev
```

### 3.3 构建
```bash
pnpm -C frontend run build
```

## 4. 后端开发

### 4.1 说明
本环境若未配置 `JAVA_HOME`，建议通过 Docker 构建/运行后端。

### 4.2 Docker 构建
```bash
docker compose build backend
```

## 5. 数据文件维护

### 5.1 节点（必需）
路径：`backend/src/main/resources/nodes.csv`

必需列：
- `id`：节点唯一 ID（建议大写英文 + 下划线）
- `name`：展示名称（中文）
- `lat` / `lng`：经纬度（小数）

可选列：`type`、`desc`

### 5.2 边（可选）
路径：`backend/src/main/resources/edges.csv`

必需列：
- `from`：起点 ID
- `to`：终点 ID

可选权重列：
- `distance_meters`（推荐）

注意：如果 `edges.csv` 缺失或为空，系统会按地理距离自动生成边。

### 5.3 管理员在线导入（先校验后更新）

接口（均为 POST，JSON 请求体）：
- `POST /api/admin/import/validate`：只校验不更新，返回 200 + 校验结果
- `POST /api/admin/import`：校验全部通过后才更新图数据；失败返回 400 + 可读错误列表，当前图保持不变

请求体示例：
```json
{
  "nodes": [{"id": "JIEFANGBEI", "name": "解放碑", "lat": 29.56301, "lng": 106.57577, "type": "地标", "desc": "..."}],
  "edges": [{"fromId": "A", "toId": "B", "distanceMeters": 800}]
}
```
说明：
- 边需双向声明（A→B 与 B→A 成对出现）；`fromId/toId` 也兼容 `from/to`，`distanceMeters` 兼容 `distance_meters`
- 校验规则（错误，阻断导入）：重复景点（id 或名称重复）、孤立节点、负权重、同一连接反向缺失、边引用不存在的景点、自环、重复边、非法坐标、必填字段为空
- 警告（不阻断）：双向权重不一致、权重为 0、图不连通（导入后系统自动补连）、多个景点坐标完全相同
- 校验逻辑位于后端服务层 `GraphImportValidator`（纯函数，见 `GraphImportValidatorTest`），编排见 `GraphImportService`

响应示例（校验失败）：
```json
{
  "success": false,
  "errors": [
    {"severity": "ERROR", "code": "EDGE_WEIGHT_NEGATIVE", "message": "边[A -> B]：负权重（-10.0 米），距离不能为负"},
    {"severity": "ERROR", "code": "EDGE_REVERSE_MISSING", "message": "边[A -> B]：同一连接反向缺失，请补充反向边[B -> A]"},
    {"severity": "ERROR", "code": "ISOLATED_NODE", "message": "孤立节点：景点[C]（朝天门）没有任何边与其他景点相连"}
  ],
  "warnings": []
}
```

## 6. 实施计划（合并）

### 6.1 目标
- 交付可运行的“重庆旅游线路规划系统”，支持一键启动、节点展示、路径规划与结果可视化

### 6.2 范围
- 前端：地图与控制面板、状态管理、错误兜底、中文化
- 后端：CSV 数据加载、数据库持久化、图构建、最短路径 API
- 运维：Docker Compose 一键启动、前端反代后端、环境变量配置

### 6.3 关键决策
- 数据输入采用 CSV（`nodes.csv` / `edges.csv`），兼容无边数据时的自动构图兜底
- 后端图算法采用 Dijkstra（节点规模小、实现清晰、可解释）
- 前端使用 Ant Design + React-Leaflet，结合 ErrorBoundary 保障稳定性

### 6.4 验收标准
- `docker compose up -d --build` 后：前端可访问、后端健康检查通过
- `/api/nodes` 返回非空节点列表
- `/api/path` 能返回可解释的路径结果；非法参数返回中文错误
- 文档齐全：架构/设计/开发/测试/用户手册/README
